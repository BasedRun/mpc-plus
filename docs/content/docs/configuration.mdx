CLI 会在当前工作目录查找以下文件之一：

```text
mpc.config.ts
mpc.config.js
mpc.config.mjs
mpc.config.cjs
```

推荐使用 TypeScript：

```ts title="mpc.config.ts"
import { defineConfig } from "@mpc-plus/cli";

export default defineConfig({
  project: {
    root: "./dist/build/mp-weixin",
  },
  release: {
    version: "1.0.0",
    description: "Release v1.0.0",
  },
  platforms: {
    wechat: [
      {
        env: "dev",
        appid: process.env.WX_APPID ?? "",
        privateKeyPath: process.env.WECHAT_PRIVATE_KEY_PATH ?? "./private.key",
      },
      {
        env: "prod",
        appid: process.env.WX_APPID ?? "",
        privateKeyPath: process.env.WECHAT_PRIVATE_KEY_PATH ?? "./private.key",
        release: {
          description: "Production release",
        },
      },
    ],
  },
});
```

## 全局配置

| 字段                  | 类型     | 说明                                         |
| --------------------- | -------- | -------------------------------------------- |
| `project.root`        | `string` | 小程序构建产物目录，上传时必填。             |
| `release.version`     | `string` | 上传版本号，微信必填，抖音可省略并自动递增。 |
| `release.description` | `string` | 版本说明，微信可选，抖音必填。               |
| `platforms`           | `object` | 平台配置集合。                               |

## 环境配置

每个平台使用数组声明多个环境。`env` 是 CLI 筛选目标的标识：

```ts
wechat: [
  { env: "dev", appid: process.env.WX_APPID ?? "", privateKeyPath: "./private.key" },
  { env: "prod", appid: process.env.WX_APPID ?? "", privateKeyPath: "./private.key" },
];
```

CLI 在读取配置文件前，使用命令行的 `--env` 作为 Vite mode。执行 `--env dev`
时会先按 Vite 规则合并：

```text
.env
.env.local
.env.dev
.env.dev.local
```

`--env prod` 会相应读取 `.env.prod` 和 `.env.prod.local`。mode 专用文件覆盖通用文件，
终端或 CI 已设置的系统环境变量优先级最高。合并结果会在配置文件执行前写入
`process.env`，因此配置继续直接读取 `process.env.WX_APPID`。

不传 `--env` 时只使用通用的 `.env` 和 `.env.local`；需要 mode 专用变量时应明确传入
`--env`。

例如 `.env.dev` 和 `.env.prod` 可以使用相同的变量名：

```dotenv title=".env.dev"
WX_APPID=wx-dev-appid
WECHAT_PRIVATE_KEY_PATH=./private.dev.key
```

```dotenv title=".env.prod"
WX_APPID=wx-prod-appid
WECHAT_PRIVATE_KEY_PATH=./private.prod.key
```

环境中的 `project` 和 `release` 会覆盖同名全局字段，适合为不同环境指定构建目录或发布说明：

```ts
{
  env: "prod",
  project: { root: "./dist/prod/mp-weixin" },
  release: { description: "Production release" },
  appid: process.env.WX_APPID ?? "",
  privateKeyPath: process.env.WECHAT_PRIVATE_KEY_PATH ?? "",
}
```

<Callout type="warn" title="不要提交密钥">
  `appid` 和 `privateKeyPath` 建议从环境变量读取。`privateKeyPath`
  是微信上传私钥文件路径，不应把私钥内容写入仓库。
</Callout>

## 抖音平台配置

抖音与微信共用 `ProjectConfig` 和 `ReleaseConfig`，同样通过环境数组声明配置。
环境内的 `project`、`release` 按字段覆盖全局配置，未设置的字段继承全局值。

```ts
export default defineConfig({
  release: {
    version: "1.0.0",
    description: "优化首页体验",
  },
  platforms: {
    douyin: [
      {
        env: "prod",
        appid: process.env.DOUYIN_APPID ?? "",
        token: process.env.DOUYIN_TOKEN ?? "",
        project: { root: "./dist/build/mp-toutiao" },
        upload: {
          channel: "1",
          needUploadSourcemap: true,
        },
      },
    ],
  },
});
```

`appid` 和 `token` 为必填配置，Token 应通过环境变量提供，不要提交到仓库。
`upload` 可选，目前开放官方 SDK 的 `channel` 和 `needUploadSourcemap` 参数；
项目目录、版本号、版本说明统一通过 `project` 和 `release` 配置。
`channel` 是抖音测试通道，与 MPC 的 `env` 环境标识相互独立。

抖音上传通过 `tt-ide-cli` 的 Node.js API 执行：先调用 `setAppConfig` 配置 Token，再调用 `upload` 上传。官方工具会将 Token 写入本机的 CLI 配置文件。

- `project.root` 必填，指向已构建的抖音小程序目录，其中 `project.config.json` 的 `appid` 必须与此处配置一致。
- `release.description` 必填，作为官方工具的 `changeLog`。
- `release.version` 可选；填写时须为 `x.y.z` 数字格式，省略时由官方工具自动递增。
- 上传不会自动复制预览链接到剪贴板，也不会输出二维码文件。

```bash
pnpm exec mpc upload --platform douyin --env prod
```

省略 `--platform` 时，会按配置依次上传微信、抖音等全部目标。
