# MPC Plus 架构规范

## 整体架构

项目采用 Monorepo 结构：

```text
packages/
├── core/
├── standard/
├── cli/
├── wechat/
├── douyin/
└── ...
````

整体依赖方向：

```text
wechat ──────► core
douyin ──────► core

standard ───► core
standard ───► wechat
standard ───► douyin

cli ────────► standard
```

禁止出现反向依赖和循环依赖：

```text
core ─────► standard
core ─────► wechat
wechat ───► standard
standard ─► cli
standard ─► tui
```

# core

`core` 是整个项目的核心运行层，只负责通用机制，不感知任何具体平台。

职责：

* 定义平台通用协议。
* 定义 `Platform<TConfig>`。
* 定义 `MPC<TPlatforms>`。
* 实现 `createMPC()`。
* 管理平台注册与获取。
* 负责 `upload` 等能力的统一调度。
* 定义平台无关的基础类型。
* 通过泛型接收外部具体平台类型。

`core` 不应该知道：

* wechat
* douyin
* standard
* cli
* tui
* 具体平台 SDK

---

# wechat / douyin / ...

平台包负责具体平台能力实现。

每个平台包只关注自己对应的平台。

职责：

* 定义平台原始配置类型。
* 定义平台最终执行配置类型。
* 实现平台上传能力。
* 实现平台预览、构建等平台特有能力。
* 封装对应平台官方 CI SDK。
* 处理平台特有的参数校验。
* 处理平台特有的数据转换。
* 导出对应的 `Platform` 实现。

例如 `wechat`：

```text
WechatConfig
ResolvedWechatConfig
wechatPlatform
```

具体平台最终需要什么参数，由平台包自己定义。

平台包可以依赖 `core`。

平台包不能依赖：

* standard
* cli
* tui
* 其他平台包

---

# standard

`standard` 是官方能力组合层。

负责把 `core` 和官方支持的平台组合成一套完整运行时。

职责：

* 引入官方平台包。
* 定义官方平台配置映射。
* 定义官方平台 resolved 配置映射。
* 定义最终的 `MPCConfig`。
* 提供 `defineConfig()`。
* 提供统一配置解析能力。
* 实现 `resolvePlatformConfig()`。
* 合并全局配置和平台环境配置。
* 实现 `createStandardMPC()`。
* 注册官方支持的平台。

例如：

```text
wechat
douyin
alipay
```

都由 `standard` 统一注册。

`standard` 可以依赖：

* core
* wechat
* douyin
* 其他官方平台包

`standard` 不能依赖：

* cli
* tui

---

# cli

`cli` 是命令行入口层。

职责：

* 定义 CLI 命令。
* 使用 `citty` 解析命令行参数。
* 加载 `mpc.config.ts`。
* 管理 CLI 运行上下文。
* 管理当前工作目录。
* 调用 `standard` 提供的配置解析能力。
* 调用 MPC runtime 执行操作。
* 处理命令行日志、错误和退出状态。

CLI 命令只负责流程编排，例如：

```text
读取参数
  ↓
获取配置
  ↓
解析平台配置
  ↓
调用 mpc.upload()
```

`cli` 不应该包含：

* 平台 SDK 调用。
* WeChat / Douyin 等具体实现。
* 平台注册逻辑。
* 通用配置合并规则。

---

# tui

`tui` 是终端交互界面入口。

职责：

* 提供终端 UI。
* 处理用户交互。
* 展示执行状态和结果。
* 调用 `standard` 提供的统一运行时能力。

`tui` 与 `cli` 是两个独立入口。

两者不互相依赖。

共同能力通过：

```text
standard
```

进行复用。

---

# 职责归属原则

新增代码时按照以下规则判断所属包：

```text
通用运行机制
→ core

具体平台能力
→ wechat / douyin / alipay

官方平台组合与统一配置
→ standard

命令行交互
→ cli

终端 UI 交互
→ tui
```

类型也遵循相同规则：

```text
通用类型
→ core

平台特有类型
→ 对应平台包

官方平台映射类型
→ standard

CLI 特有类型
→ cli

TUI 特有类型
→ tui
```

任何情况下都应保持单向依赖，避免跨层实现和循环依赖。
